# Documentation

- **Keep documentation next to the code** it describes, in the formats the project already uses.
- **README** explains what the project is, how to build, test and run it, and where to find more.
- **Public APIs** have reference documentation (doc comments) describing purpose, parameters, return values,
  errors and examples where helpful.
- **Architecture** is described at a level that helps a newcomer: context, main components, key decisions
  (ADRs). Use diagrams-as-code where the project already does.
- **Accuracy over volume.** Update documentation in the same change as the behaviour it describes. Delete
  documentation that is no longer true.
- **Be explicit about status:** label content as current behaviour, recommendation, or proposal.
- **Never document secrets** or internal endpoints in public documentation.
- Write plainly: short sentences, active voice, consistent terminology, examples that actually run.
