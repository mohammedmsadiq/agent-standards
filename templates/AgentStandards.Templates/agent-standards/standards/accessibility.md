# Accessibility

Applies to anything with a user interface (web, desktop, mobile) and to generated documents.

- Target the project's stated standard, or WCAG 2.2 level AA when none is stated.
- Use native, semantic controls before custom ones; custom controls need correct roles, names, states and
  keyboard behaviour.
- Every interactive element is reachable and operable with a keyboard (or switch/assistive input on mobile), has a
  visible focus indicator, and a logical focus order.
- Provide text alternatives for meaningful images and icons; mark decorative images as decorative.
- Do not rely on colour alone; maintain sufficient contrast (4.5:1 for normal text).
- Support text scaling and dynamic type without clipping or loss of function.
- Label form fields and announce validation errors to assistive technology.
- Respect reduced-motion and other user preferences.
- Test with at least one screen reader and keyboard-only navigation for significant UI changes.
